# CLAUDE.md — project memory

K-M spectral recipe solver for Golden Heavy Body acrylics. React/Vite +
optional Tauri shell. The physics lives in `services/physicsEngine.ts`; all
optical data in `constants.ts` is generated by `generate_constants.py`.

## Optical model & conventions (do not change one side without the other)

- Two-constant Kubelka-Munk mixing: `K_mix = Σ c·K_i`, `S_mix = Σ c·S_i`,
  `R∞ = 1 + q − √(q² + 2q)` with `q = K_mix/S_mix`. 16 bands, 400–700 nm / 20 nm.
- Saunderson correction constants **must stay in sync** between
  `physicsEngine.ts` and `generate_constants.py`:
  - Ingest (measured → internal): `k1 = 0.03`, `k2 = 0.6`. k1 is deliberately
    *below* the textbook 0.04 because the drawdown data has a measured
    reflectance floor of ~3.7% (gloss included); k1 ≥ that floor clamps
    saturated bands and amplifies floor noise into huge K/S.
  - Output (internal → displayed/predicted): specular **excluded** (`k1 = 0`,
    same k2). The solver models paint at complete hiding viewed without
    glare, matching the 6mm fully-opaque calibration data.
- `PIGMENT_KS_FIT` in `constants.ts` (between `BEGIN/END GENERATED` markers,
  machine-written) holds per-pigment `k[16]`/`s[16]`. Pigments absent from it
  fall back to masstone K/S with `s = 1` (single-constant equivalent).
- Engine currently uses CIE 1931 2° CMFs for display/solving; the Python
  calibration uses CIE 1964 10° (matches Golden's D65/10° data). Known,
  accepted inconsistency — display-side only.

<cielab.xlsx> --write constants.ts`. Self-test (no data needed):
`--selftest`. Engine checks: `npx tsx scripts/engine-smoke.ts`.

## What the current calibration is (and is not)

- Per-pigment scalar γ multiplies the masstone-derived internal K/S so the
  predicted complete-hiding color matches the measured 6mm Lab. Opaque paints
  fit γ ≈ 0.8–1.3; transparent ones ~1.5–3.1 (their drawdowns were corrupted
  by the white card showing through). Whites (absent from the drawdown sheet)
  are fitted from their thin/opaque Lab pair via the finite-thickness K-M
  film equation; zinc white s_rel ≈ 0.42.
- **Hard limitation learned the hard way**: for dark transparent pigments the
  film sits at the gloss floor, so this data pair determines only the ratio
  k/s, never absolute tinting strength. A free per-wavelength (k, s) fit
  collapses their strength absurdly (10% dioxazine in white predicted
  near-white) — that's why everything stays on the `s = 1` convention with a
  γ correction. Real per-pigment scattering needs **tint measurements**
  (paint : titanium white at known weight fraction). The fitter for that
  already exists (`--tints tints.csv`, format in the module docstring) and is
  validated by `--selftest`; it supersedes γ per pigment when data arrives.
- 10 paints keep the uncalibrated masstone fallback because the two Golden
  datasets disagree (ΔE > 8, likely formulation changes): Nickel Azo Yellow,
  Perm Green Light, Permanent Maroon, Pyrrole Red Dark, Quin Magenta, Quin
  Nickel Azo, Transparent Brown/Red/Yellow Iron Oxide, Ultramarine Blue.

## Dead ends already ruled out (don't re-litigate)

- Berns "Artist Acrylic Paint Spectral, Colorimetric, and Image Dataset"
  (grayskyimaging.com): the Excel spectral database with fitted K-M
  coefficients is **no longer downloadable**; only the paper PDF and the
  synthetic-target TIFF remain. The TIFF's 840 patches are sorted by hue
  angle with the patch key lost — unusable.
- Guessed per-pigment scattering values from opacity ratings: tested, makes
  transparent-pigment tints *weaker* (k is capped by the measurement floor);
  reverted.
- Remote-env note: general web downloads are blocked (only package
  registries); get data files from the user via chat upload or their
  Google Drive.

## Possible next steps

- Golden's Virtual Paint Mixer (justpaint.org) likely ships real two-constant
  per-paint data as client-side JSON — a DevTools scrape by the user would be
  the best remaining data source.
- User DIY tint drawdowns (1:9 with Titanium White, scan/photo vs reference)
  feed the existing `--tints` fitter; only needed for transparent pigments.
- Consider switching the engine to 10° CMFs for consistency with the data.
